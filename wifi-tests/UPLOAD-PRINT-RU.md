# Проверка отправки из ElegooSlicer

> Для установки опубликованного последнего комплекта используйте [README](../README.md) и [актуальную инструкцию](../docs/INSTALL-RU.md). Ниже сохранены заметки отдельного этапа разработки; пути dist относятся к локальным сборкам.


## Новая прошивка

Нужно обновить основную плату файлом
`dist/NEPTUNE3_MKS_WIFI/ZNP_ROBIN_NANO.bin` через microSD, как в FLASHING-RU.md.
Это новое окружение, не прежний `NEPTUNE3_MKS_WIFI_DIAG`. Экран не обновляем.
Полный путь на этом ПК:

```text
<папка проекта>\dist\NEPTUNE3_MKS_WIFI\ZNP_ROBIN_NANO.bin
```

Сборка: `./wifi-tests/build.ps1 -Environment NEPTUNE3_MKS_WIFI`.
Тесты: `./wifi-tests/run-tests.cmd`. Ctrl+Shift+B в нашем workspace теперь
собирает именно новое окружение. Исходная диагностика остаётся доступна отдельно.

## Что реализовано

- Смена UART2 115200 -> 1958400 -> 115200, GPIO управления потоком из IRQ,
  RX-буферы 4096 байт. Следующий пакет приостанавливается с первого байта текущего.
- Отдельный SD writer: временный `.TMP`, точный порядок/длина фрагментов,
  синхронизация и переименование в `.GCO` только после последнего блока.
- Пустой завершающий блок MKS и нулевое дополнение до 1024 байт.
- Отказ при занятом принтере/карте, ошибки записи, удаление своего неполного файла,
  таймаут и возврат к обычной скорости. Пользовательские файлы не перезаписываются.
- M991/M27/M992/M994/M997, M20/M21, M23/M24, M25/M26, диагностический M998.
- Запуск только выбранного завершённого Wi-Fi-файла, через штатную очередь M24.
  При старте открывается страница печати TJC, включаются штатные флаги экрана.
  Сам факт завершения загрузки печать не запускает.

Имена: корректный UTF-8, включая кириллицу, ASCII-буквы, цифры, пробелы,
`_ - ( ) .`, не более **90 байт UTF-8**, расширения `.gcode`, `.gco`, `.gc`, `.g`.
Папки и управляющие символы не поддерживаются. Кириллические имена получают
короткий ASCII-псевдоним на карте, исходное имя сохраняется для команды M23.
Если основа исходного имени укладывается в 8 допустимых символов, на SD
сохраняется понятное имя: `M6x12.gcode` -> `M6X12.GCO`. Для длинных имён
или совпадения с существующим файлом создаётся уникальный `Nxxxxxxx.GCO`; команда M23
с исходным длинным именем связывается с ним. Повторная отправка создаёт новую
копию; старую можно удалить на ПК. Соответствие исходного имени хранится в RAM
только для последней загрузки; после перезапуска для сетевого старта нужно
отправить файл снова. С экрана сохранённые файлы можно выбирать по псевдониму.
В процессе загрузки обработка меню экрана приостанавливается, задачи температуры
и watchdog продолжаются. Не пользоваться SD-картой параллельно загрузке.

## Сначала проверка без печати

После обновления оставь принтер подключённым к домашней сети. Текущий адрес:
`192.168.1.50` (после перезапуска DHCP может назначить другой).
Из терминала в корне репозитория:

```powershell
python wifi-tests/network-upload-test.py --host 192.168.1.50
```

Скрипт сначала проверяет наличие M998 в новой прошивке, затем отправляет
тестовый файл ровно 2030 байт. Это две полные порции данных по 1015 байт плюс
пустой LAST-блок — важная граница протокола. В файле только комментарии и M117,
команд движения/нагрева нет. **Скрипт не отправляет M23/M24 и не начинает печать.**

PASS означает: ESP принял HTTP-данные, а основная плата отдельно подтвердила
`M998 SAVED 2030 Nxxxxxxx.GCO`. Успех HTTP сам по себе недостаточен: штатная
прошивка ESP может ответить раньше завершения записи на SD.

После PASS для первой полной проверки: выключи принтер, скопируй с microSD
указанный `.GCO` на ПК и сравни его SHA256 с показанной скриптом суммой
эталонного `wifi-tests/UPLOAD_TEST.GCO`. Они должны совпасть.
Перед первой настоящей печатью также проверяем обрыв загрузки и повторную отправку.

Отправка произвольного готового файла без запуска печати:

```powershell
python wifi-tests/send-file.py "model.gcode" --host 192.168.1.50
```

Скрипт проверяет статус IDLE и подтверждение SAVED с точной длиной, но не
отправляет M23/M24. Для больших файлов таймауты увеличены, есть прогресс.
M6x12.gcode (20667242 байта) аппаратно загружен за 298.4 с под N8AFF0FF.GCO.

## Настройка ElegooSlicer

В параметрах сетевого подключения профиля **Neptune 3 Pro** выбери тип хоста
**MKS**. Адрес хоста: **192.168.1.50**, без `http://`, пути и `:8080`.
Для MKS приложение само использует HTTP 80 для файла и TCP 8080 для команд.
API key не требуется. Нажми Test/Проверить: используется запрос M105.
Если в интерфейсе нет выбора MKS, нужен скриншот настроек подключения,
чтобы найти этот пункт в установленной версии, а не выбирать другой протокол.

Исправление совместимости 2026-11-12: прежняя прошивка отвечала `ok T:...`
одной строкой, а ElegooSlicer TCPConsole ждёт строку, равную ровно `ok`.
Периодические температуры продлевали ожидание без конца. Новая прошивка
отвечает отдельными строками `T:...` и `ok`; M991 остаётся без подтверждения.
Проверка без риска зависания приложения:

```powershell
python wifi-tests/check-slicer-connection.py --host 192.168.1.50
```

Тест ограничен 8 секундами и отправляет только M105. На прежней прошивке
подтверждён FAIL: приходит `ok T:...`, отдельного ok нет. После обновления
ожидается PASS, затем можно нажать «Тест» в самом ElegooSlicer.

Фильтр TJC теперь поддерживает `.gcode`, `.GCO`, `.GC`, `.G` независимо от
регистра и берёт короткое имя, если FAT не содержит длинного. Ранее загруженные
псевдонимы тоже должны появиться после обновления основной платы. Экран не прошиваем.

Сначала нарежь маленькую модель с корректным профилем/материалом и отправь
**только загрузку** с коротким латинским именем, например `CUBE.gcode`.
После подтверждения файла и проверки калибровки можно использовать
«Загрузить и начать печать»: приложение отправит M23 с именем, затем M24.
Первая печать — под наблюдением. Не запускай сетевой старт во время другой
печати, паузы, калибровки или ручного движения принтера.

Если установлена сборка до поддержки UTF-8, русское имя вроде
`EN3Pro_0.4_Куб_...gcode` отклоняется до приёма данных, а ESP сообщает общий
HTTP 500 NO DATA RECEIVED. На принтере подтверждено: одинаковое содержимое с
«Куб» даёт 500, с «Cube» — 200 и приём заголовка. Это отдельно от подтверждения
SAVED: на очень коротком файле обнаружена дополнительная ошибка записи во время
приёма UART-дополнения. Новый FragmentBlock откладывает всю запись до приёма
1024 байт; регрессия проверяет, что до последнего байта SD не меняется.
Временный обход ошибки имени — латинское имя
в диалоге отправки. Новая сборка принимает UTF-8 и при загрузке, и в M23;
причина последнего отказа также доступна через ` M998` после `ERROR:`.

На реальном устройстве подтверждены загрузки 2030 и 101500 байт, обработка
обрыва на 960/20000 байт и успешная повторная загрузка после него. Для запросов
статуса в TCP нужен ведущий пробел: ` M998`, поскольку ESP в режиме ROBIN
перехватывает строки, начинающиеся непосредственно с M998, и сам отвечает ok.
Сравнение SHA256 файлов с карты, старт печати и действия TJC ещё требуют проверки.
При ошибке загрузки сохрани сообщение и USB-журнал, не повторяй старт вслепую.

## Сверенные исходники протокола

- [Makerbase MksWifi.ino](https://github.com/makerbase-mks/MKS-WIFI/blob/master/firmware_source/MksWifi/MksWifi.ino): FILE_BLOCK_SIZE=1015, пакет 1024, скорость 1958400, сигналы READY, последний пустой фрагмент.
- [ElegooSlicer MKS.cpp](https://github.com/elegooofficial/ElegooSlicer/blob/main/src/slic3r/Utils/MKS.cpp): POST `/upload?X-Filename=...`, TCP 8080, задержка перед M23/M24.
