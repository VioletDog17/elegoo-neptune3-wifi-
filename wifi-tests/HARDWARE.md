# ZNP Robin Nano_DW V2.2: проверенная карта интерфейсов

> Карта контактов остаётся актуальной; описания диагностики ниже относятся к раннему этапу. Текущие возможности и статус проверки: [README](../README.md), установка: [INSTALL-RU](../docs/INSTALL-RU.md).


Источник: `neptune3pro-main/PCBA/Mainboard/ZNP Robin Nano_DW V2.2 SCH.pdf`,
ревизия в штампе V2.2_001, дата 2022-09-13. Сверены листы 2, 9 и 10.
Номера выводов ниже относятся к MCU/сигналам, не к ориентации разъёма.

| Назначение | Вывод MCU | Сигнал схемы |
|---|---|---|
| MCU -> Wi-Fi RX | PA2 / USART2 TX | TXD2 |
| Wi-Fi TX -> MCU | PA3 / USART2 RX | RXD2 |
| Сброс Wi-Fi, активный LOW | PA1 | WIFI_CTRL |
| Boot/IO0 модуля | PA0 | WIFI_IO0 |
| Управление потоком, HIGH = пауза приёма | PC15 | WIFI_IO1 |
| MCU -> экран | PA11 / USART6 TX | TXD6 |
| Экран -> MCU | PA12 / USART6 RX | RXD6 |
| USB-UART -> MCU | PA9/PA10 / USART1 | TXD1/RXD1 |

Wi-Fi и дисплей **не делят UART**. На листе 9 M1 ROBIN-WIFI питается от
3.3 V; отдельный J17 несёт +5 V, GND, TXD2, RXD2. J17 не предоставляет
сигналы управления модулем. Эта таблица не является инструкцией подключать
питание модуля к +5 V.

## Соответствие исходникам

- `Configuration.h`: `BOARD_MKS_E3D_V2`, `SERIAL_PORT 1`,
  `RTS_AVAILABLE`, `TJC_AVAILABLE`.
- `Conditionals_adv.h`: `LCD_SERIAL_PORT 2`, `LCD_SERIAL_PORT_2 6`.
- `DGUSDisplay.cpp`: исходная прошивка запускает и читает оба LCD-порта.
  В диагностическом окружении первичный DGUS отключён, USART6 TJC сохранён.
- `PlatformIO.zip/PlatformIO/variants/MARLIN_MKS_E3/PeripheralPins.c`:
  USART2 PA2/PA3, USART6 PA11/PA12 (первые варианты назначения).
- `wifiSerial.h`: штатная скорость 115200, загрузка 1958400 бод.
  Диагностика работает только на 115200 и не переключается на загрузку.
- `wifi_module.cpp`: принтер отправляет текстовые ответы в кадрах типа 2.
  HIGH на WIFI_IO1 останавливает передачу модуля, LOW разрешает.

Схема и штатная сборка указывают STM32F401RCT6. Пользователь прочитал на
своём MCU STM32F402RCT6. Это расхождение зафиксировано; настройки процессора
оставлены заводскими (`marlin_MKS_F401RC`, 84 MHz, offset 0x8000).
Успешная сборка сама по себе не подтверждает аппаратную совместимость MCU.
Снимок исходников TJC_029 также пока не сопоставлен с установленной 1.1.5.1.

## ElegooSlicer 1.5.3.5

В локальном `C:/Program Files/ElegooSlicer/ElegooSlicer.dll` найдены класс
`Slic3r::MKS`, сообщения проверки соединения MKS и строки
`http://%1%/upload?X-Filename=%2%`, `http://%1%/upload_serial`.
Это подтверждает наличие реализации MKS в приложении. Протокол по сети,
выбранный профиль принтера и прошивка ESP8266 аппаратно ещё не проверены.

## Диагностическое окружение

Подготовка исходников: `python wifi-tests/prepare-build.py`.
Сборка из корня репозитория:

```powershell
./wifi-tests/build.ps1 -Environment MKS_E3_V2
./wifi-tests/build.ps1 -Environment NEPTUNE3_MKS_WIFI_DIAG
```

Нужны Python и PlatformIO 6.1.18 (`python -m pip install platformio==6.1.18`).
На текущем ПК отдельная копия PlatformIO находится в игнорируемой `.tools/pio`.
Скрипт использует её автоматически, пакеты STM32 хранятся в `.platformio-wifi`.
Он не выполняет загрузку прошивки на принтер.

Диагностика включается только в `NEPTUNE3_MKS_WIFI_DIAG`, обычное окружение
остаётся без Wi-Fi. UART RX-буферы диагностического окружения увеличены до
2048 байт: полный MKS-кадр не помещается в штатные 128 байт.
Выходной файл диагностического окружения — `ZNP_WIFI_DIAG.bin`;
это имя для различения результатов сборки, не инструкция по прошивке.

Поддержаны входящие MKS-кадры 0 (IP/состояние), 1 (команды), ответы на
`M115`, `M105`, `M997`. Команды должны завершаться LF; CR перед LF допустим.
Движение, установка температуры, загрузка, запуск печати и прочие команды
отклоняются. Поля SSID/пароля не выводятся в журнал USB.

Тесты `run-tests.cmd` проверяют декодирование, ограничения передачи,
восстановление после ошибок, таймауты, переполнение millis(), разбиение
команд и отбрасывание повреждённых/слишком длинных строк.

Аппаратная проверка ещё не выполнена. Следующая стадия — SD writer,
буферизация при 1958400 бод и полноценное управление печатью. До неё нельзя
считать эту сборку готовым решением для отправки G-code из слайсера.
