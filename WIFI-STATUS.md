## Актуально: WIFI NAMES — исходные имена (12.11.2026)

Новый комплект `dist/NEPTUNE3_WIFI_NAMES`, ZIP рядом, инструкция `WIFI-NAMES-UPDATE-RU.md`. Требуются bin и tft; на устройстве ещё не проверены. Добавлены `filename_metadata.h` (versioned UTF8 record, size/FNV checksum), `sd_names.h` (SD read/resolve), транзакционное сохранение `.NAM` при успешной загрузке в SdStore. При ошибке метаданных отменяется загрузка, удаляются только зарезервированные имена. Диск остаётся 8.3; экран/печать/M20/M994 используют исходное имя. CardRecbuf buffers96. RTS_SndData string для TJC теперь сразу возвращает, чтобы не переполнять отключённый legacy DGUS buffer26; nonTJC ограничен размером буфера. Исправлен sidecar picname buffer при длинных именах. Старые загрузки требуют повторной отправки, нет метаданных. Исходные имена сохраняются после reboot; неоднозначный сетевой M23 после reboot отклоняется, latest upload выбирается точно по RAM alias.

HMI `NEPTUNE3_WIFI_NAMES.HMI` копирует STYLE и меняет только printpause.t0.txt_maxl 36→128. Сравнены все события/атрибуты; дизайн сохранён. - Модуль настроен пользователем в домашнюю сеть, адрес <PRINTER_IP>. HTTP GET / возвращает 200 и страницу MKS WIFI.

- M115 через TCP сообщает `FIRMWARE_NAME:TFT28/32`: это ответ самого ESP (сверено с исходниками MKS-WIFI), а не идентификатор основной платы. USB M115 продолжает использоваться для версии Marlin.
- В TCP также видны `Error:WiFi diagnostic mode; command disabled`: штатный модуль автоматически опрашивает M991/M27, пока не поддержанные диагностикой. По исходникам MKS-WIFI эти запросы повторяются каждые 5 секунд. Перед подключением слайсера нужно расширить статусные ответы.
- Проверка не включала движение, нагрев, изменение настроек, загрузку файла или печать. Результаты TCP сохранены локально в wifi-network-test.log.
