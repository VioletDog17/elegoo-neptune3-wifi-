# Автономный Wi-Fi host

Новая прошивка для **MKS Robin WIFI V1.1 / ESP8266, 4 MB flash, DOUT**, совместно с основной платой этого проекта с API v2. Веб-панель хранится сжатой во flash вместе с программой; SPIFFS и отдельный WebView устанавливать не нужно. ПК, облако, CDN и локальный мост не требуются.

## Сборка

Из корня репозитория с установленным PlatformIO:

```powershell
python -m platformio run -d esp8266
```

Результат: `esp8266/.pio/build/mks_robin_wifi/firmware.bin`. Для первоначального обновления через штатную страницу MKS его копируют под именем **MksWifi.bin**. Не путать с BIN основной платы. Платформа `espressif8266@4.2.1`, Arduino core 3.1.2; линкер `eagle.flash.4m3m.ld`, режим DOUT. Встраивание HTML/CSS/JS выполняет `embed_web.py`.

## Обмен с основной платой

UART0: GPIO1 TX / GPIO3 RX, 115200; передача файла 1958400. GPIO4 — готовность основной платы, GPIO0 — запрос передачи, HIGH при простое. Реализация использует формат кадров MKS A5/type/lengthLE/payload/FC. Передаются целые блоки 1024 байта, готовность проверяется между блоками. `M794` включает подтверждение предложения файла; исключение 4 передаётся на 115200, исключение 2 после сохранения также на 115200.

API основной платы: `M995` — ограниченный JSON статуса; `M795` — список корневых G-code с оригинальными именами; `M996 id action` — проверяемые команды управления; `M796 id action [alias]` — запуск/пауза/продолжение/остановка с идентификатором ответа. Принятие команды не означает завершение движения. Стандартные MKS TCP-команды на порту 8080 и сырой HTTP `/upload?X-Filename=...` сохранены для слайсера.

Поправка `0.2.0-dev-uart2`: скорость меняется через `updateBaudRate`, без `end/begin`. При передаче блока между байтами выдерживается 12 мкс, каждые 64 байта отдаётся время Wi-Fi. Непрерывный поток в первой версии воспроизводимо давал `Invalid UART frame`; дозированная передача прошла аппаратную проверку. `/api/diagnostics` показывает этап и количество отправленных байтов последней загрузки без сетевых паролей.

HTTP читает файл порциями по 1015 байт, без загрузки всего тела в RAM. Лимиты: 32 MiB на G-code, 90 байт UTF-8 на имя, до 128 файлов в корне, сканирование до 1024 записей. Вложенные каталоги в новой панели не поддерживаются. Список недоступен для обновления при открытом печатном файле; последний полученный список остаётся в RAM модуля. Удаление файлов, камера и история печати не реализованы.

## Сеть и доступ

Сохраняется размещение SSID/ключа/режима в EEPROM штатного MKS. Резервная точка **NEPTUNE3-<chip ID>**, пароль **neptune3wifi**, адрес `http://192.168.4.1/` работает параллельно с STA. Настройки Wi-Fi доступны в панели. Пароль сети не возвращается через API. mDNS: `http://neptune3.local/`, если поддерживается клиентом.

Это локальный HTTP host без учётных записей и HTTPS. POST панели проверяет Host, Origin и случайный токен текущей загрузки; это защита от случайных запросов с чужого сайта, не аутентификация пользователя. Legacy MKS загрузка/TCP остаются без токена. Использовать в доверенной локальной сети, без проброса портов. Резервный AP имеет общий известный пароль; учитывайте это при размещении принтера.

После установки обновлять модуль можно утилитой `wifi-tests/update-wifi.py`: она читает сессию, проверяет простой/выключенный нагрев и отправляет сырой BIN в `/api/update`. Передача прошивки не выполняется автоматически при сборке. Перепрошивка MCU/TJC этим API не поддерживается.

## Проверки

Сборка и тесты на ПК не заменяют проверку платы. 13 ноября 2026 подтверждены OTA нашей прошивки, чтение статуса, выключение нагрева и загрузки 43/217141 байт; многоблочный файл с кириллицей появился в списке с точным размером. Печать тестов не запускалась. Полная аппаратная проверка движения, печати/паузы и смены Wi-Fi ещё требуется; общий `hardware_tested` остаётся false.

Формат MKS изучен по [исходникам Makerbase](https://github.com/makerbase-mks/MKS-WIFI). Новая реализация не требует модификации Arduino core штатного проекта.
